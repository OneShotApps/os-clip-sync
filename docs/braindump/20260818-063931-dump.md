There is a consideration for us to use Flutter in the mobile applications, and that is perfectly acceptable. We could also use Flutter on the front end if we wanted to. However, the key is that it must compile into a native application for that user interface.

And we also do not want to use a single application that's deployed everywhere. We want the applications that we deploy to be as small as possible. So we would potentially have the UI artifacts in a separate, a separate folder or separate package and have it have the mobile UI elements pulled into the mobile application application and the desktop elements pulled into the desktop application to try and keep them as small as possible.

What we don't want is we don't want a single Flutter application that somehow has all of the resources for all of the applications packaged into the same delivered binary.
