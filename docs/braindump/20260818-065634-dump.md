To clarify what I was referring to about the single-user system, the Docker container will be hosted. It will allow anybody to register and create an account. But when that person registers and creates their account, they're essentially creating a clipboard object. The top-level object is that clipboard. Whenever they log in inside of one of the client applications, they're logging in and getting access to their clipboard.

The reason why I'm pointing this out is because it would be impossible for there to be collisions with multiple devices pushing content to the clipboard at the same time since it's one user. And so that one user would have to, you know, even if they were using multiple handheld devices, they'd have to pick one up and put the other down. So we don't need to worry about collisions. Whatever the last received blob of data is from the client, that is what wins.

We also don't care about clipboard syncing, right? There's no concept of synchronization. So if we have 10 machines that user has, but only five of them are online, whenever an item is copied to the clipboard buffer or the clipboard server, it'll be pushed down to the ones that are online. The ones that are offline, when they come back online, we're not going to worry about catching them up or synchronizing or whatever. That user can still go to the clipboard in the UI of the application and tap on it or click on it and copy the clipboard item from the previous 10 minutes or whatever into the buffer.

Now there's a scenario where a user doesn't want something that they're about to copy to be pushed to the clipboard. And so for that reason, the Finder application or the system tray application will let them pause synchronization so they're not pushing the item they copy into the other computers or devices. That allows them to copy something temporarily that may be sensitive that they don't want stored.

Clipboard history remains forever in the database. We're not going to worry about deleting anything unless the user wants to delete it. And they can do so from the UI of the application.

We're also not going to limit the number of devices they use, nor are we going to worry about revocation of keys or anything like that at this point.
